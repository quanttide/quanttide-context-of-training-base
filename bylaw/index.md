法理：

你们不是“用工”，是建了一个仿真经营体（Simulation Company）。

关键不是项目假不假，而是控制权在教学侧，不在业务交付侧。

基础：

• 不按正式员工排产，不背业务 KPI

• 不独立交付客户项目，不替代在岗工程师

• 有课程表/周计划/导师记录/成长档案

• 产出：练习代码、脱敏数据集、实验报告，不进生产主干（或走单独 fork）

• “本贡献为自愿、非持续性、无对价行为”

• “双方不构成劳动/劳务/雇佣关系”

• “贡献者自行承担时间与设备成本”

• “公司无义务接收任何 PR，也无续约/转正承诺”

• “知识产权依 OSS 许可证授予，非职务转让”

知识产权：

① 贡献者协议（CLA / CAA）

• 代码按开源许可证提交（如 MIT/Apache-2.0）

• 可选：签署 CLA 做永久非独占许可，或 CAA 做版权转让 

• 保留署名权、保留个人仓库使用自己代码的回授许可

• 排除背景代码（background IP）不转让

财务激励

好，我直接说透：你想要的是“学员产出能回流到公司主业，但不触发劳动关系”。

这个诉求本身不违法，但路径极其狭窄，而且不能叫“吸收产能”，得叫“教学资产沉淀后的二次利用”。

给你三条路，按风险从低到高排列：

方案一：教学 fork + 人工筛选回流（最稳）

逻辑：学员在模拟公司的 GitHub 组织里写，产出归教学资产池。公司正式员工从池子里“挑选”有价值的片段，重写后并入主业。

具体操作：

1. 学员提交到 teaching-org/xxx-project（模拟组织）

2. 教学结束后，导师做一次“资产盘点”：标记有价值的算法片段、数据处理脚本、文档框架

3. 公司正式员工（不是学员）把这些片段拿出来，重写/重构/适配后合入 company-org/main

4. 重写比例建议 >60%，避免著作权纠纷

5. 学员在贡献记录里署名，但版权依《IP授权协议》已授权给基地

合规关键：

• 学员的产出从未进入公司生产仓库

• 中间有一道“人工翻译层”（正式员工重写）

• 学员不接触真实客户数据、不参与生产决策

代价：你需要花正式员工的工时做筛选和重写，不是白嫖。

方案二：竞赛/悬赏制（风险可控）

逻辑：不搞“持续贡献”，改成“定点悬赏”。学员凭本事拿奖金，公司拿到可用代码。

具体操作：

1. 教学过程中，导师发布“悬赏任务”（如：实现某个脱敏场景下的算法优化）

2. 学员自愿认领，完成后代码走 PR 到 teaching-org/contest

3. 导师评审，前三名发奖金（500-5000 不等，单次结算）

4. 获奖代码经正式员工 review 后，可合入公司仓库

5. 没获奖的代码留在教学仓库，不回流

合规关键：

• 每次是独立民事交易，不是持续性用工

• 奖金是“悬赏报酬”，不是“工资”

• 学员可以拒绝参加，不影响实训评价

优势：直接买到可用的高质量产出，成本低于招实习生。

方案三：学员持股/收益分成（长线但合法）

逻辑：学员的优质产出不买断，而是约定“未来收益分成”。

具体操作：

1. 学员在实训期间开发的某个模块，经评估有商业价值

2. 签《收益分成协议》：公司可商业化该模块，学员获得未来收入的 X%（建议 1-5%）

3. 分成周期：1-2 年，按季度结算

4. 学员不拿工资，但有机会拿到“睡后收入”

合规关键：

• 这是投资收益关系，不是劳动关系

• 学员承担“可能一分钱没有”的风险

• 适合特别优秀的产出（如一个新算法、一个高效工具链）

优势：激励最强，学员有动力写好代码。

劣势：财务核算复杂，适合高价值项目。


实习证明：

你们前提是：

• 独立实训 GitHub 组织

• 项目是脱敏/仿真，不对外履约

• 学员自主排期、无打卡替代生产

• 三方协议 + 教学日志 + 导师复盘

• 产出经重写后才回流主业

在这种事实下：

• 发《实训证明 / 模拟岗位实践证明》✅ 安全

• 发《实习证明》字样也没事，只要内容不虚构“真实用工”

• 别发“工作证明”“任职证明”“离职证明”

补充边界：

• 学员已毕业、且开始固定坐班+规律给钱+干真业务 → 哪怕发的是“实习证明”，也挡不住劳动关系认定 

• 在校生教学实习：发证明 ≠ 劳动关系，但出事按民法典过错担责（买好意外险）

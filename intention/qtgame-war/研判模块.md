敌情研判模块 · 任务书
明白，标准改为现在就能开工、不依赖引擎和任何未建模块。按这个标准选下一个：敌情研判模块（参谋把零散情报拼成敌情估计的那一步）。它的输入是一份手写就能造的情报记录文件，输出是信念状态，全程纯逻辑运算——不碰引擎、不碰界面、不碰认知管线的其他环节，今天就能开始写实验卡。
1. 模块定位
参谋的脑子：读入逐条送达的情报（主张、来源、可信度、送达时间），为每个敌军建制持续维护一份当前研判——估计在哪、估计多少兵力、多大把握、依据哪几条。它是：
• 迷雾玩法的成品车间——过滤、延迟、失真都是工序，研判才是出成品的一环，玩家在 hj map 和“问参谋”卡上看到的正是它的产出；
• 决策日志中 belief_snapshot 的生产者——上一份任务书里的快照，源头在这里；
• “被假情报骗到”的发生地——骗局成立与否，取决于研判规则合不合理。
2. 前置依赖（几乎没有）
• 信念状态与情报条目的 schema 已定稿（阶段 1 认知 schema，本就是最先定稿的东西）；
• 输入不需要管线：情报记录就是 JSONL 文件，手工构造一批测试情报即可开工；
• 输出不需要消费者：信念状态落成 JSON 文件，暂时没人读也能独立验收；
• 不依赖引擎、不依赖 rng、不依赖 UI。
插入时点：阶段 1 定稿认知 schema 后即可动工，比原计划（阶段 3）提前两个阶段——它是全项目里少数能“提前量产”的核心机制。
3. 输入 / 输出
输入（手工可造的情报记录，格式与情报账本一致）：
{”id“: ”intel_0219“, ”turn“: 47, ”unit“: ”enemy_div_72“,
 ”claim“: {”type“: ”sighting“, ”position“: [116.51, 34.63], ”strength_est“: 0.7},
 ”source“: {”kind“: ”recon“, ”by“: ”cpla_4corps“, ”reliability“: 0.6}}
输出（每个敌军建制一份当前研判，每回合更新落档）：
{”turn“: 47, ”unit“: ”enemy_div_72“,
 ”est_position“: [116.48, 34.60],
 ”est_strength“: 0.68,
 ”confidence“: 0.52,
 ”based_on“: [”intel_0213“, ”intel_0219“],
 ”stale_turns“: 2}
研判规则第一版（全部查表，无智能）：
规则	内容
新证优先	估计值以最新可信情报为主，旧情报按陈旧度衰减权重
众证加权	多条情报对同一建制给出不同位置时，按 可信度×新鲜度 加权平均
冲突降信	情报之间互相矛盾（方位差超过阈值）→ confidence 下降，而非强行取平均
断供渐盲	连续 N 回合无新情报 → confidence 逐回合衰减，估计位置冻结并标注 stale_turns
依据留痕	每次更新记录 based_on 编号清单，只引用 turn ≤ 当前回合的条目
4. 四条实现铁律
1. 研判只认输入文件——函数签名就是“情报记录序列 → 研判状态”，除参数表外不读任何其他东西。这保证它永远可以独立测试、独立复现，也天然杜绝偷看真相（输入里根本没有 truth 字段的位置）；
2. 每份研判可追溯——based_on 必须完整：抽查任何一次研判，人工按规则表重算，必须能从它引用的几条情报推出同样的结果。参谋判断和账目一样，要经得起复核；
3. 规则表即参数，版本指纹随出——阈值、衰减系数全部收敛到一张参数表并带 hash（与决策日志的 weights_hash 同一体例），改规则必须留版本痕迹；
4. 确定性从第一版就有——纯函数、无随机、无时间依赖，同输入永远同输出。这一条让它天然通过 CI 的确定性断言，零额外成本。
5. 验收断言（全部用手工夹具，不需要引擎）
• 金标准研判夹具 ×3：手写三段情报序列（单调推进 / 互相矛盾 / 中途断供），手算期望研判，逐回合比对；
• 冲突降信：两条位置矛盾且可信度相近的情报，断言 confidence 低于只有单条时的值；
• 陈旧衰减单调：断供后 confidence 随回合单调下降，位置冻结不变；
• 时序铁律：构造一条 turn 晚于当前回合的情报混入输入，断言被拒收——研判永不引用未来情报（这条是与决策日志链路对质的本模块侧防线）；
• 可追溯抽查：随机抽 10 次研判，按规则表人肉重算，结果必须一致；
• 参数指纹：改任一阈值 → hash 变化 → 同夹具研判结果 diff 可归因。
6. 使用方式（第一版）
不建界面，一个命令：
hj assess records/intel.jsonl —params params/assess_v1.json —turn 47
# 输出 records/beliefs_turn47.json
开发期它就是个独立小工具：拿手写情报序列喂它，看研判曲线合不合常识。将来认知管线建成，同一函数原样嵌入，输入从文件换成管线内存流——接口不变，插上就用。
7. 明确不做
• 不做敌方欺骗逻辑（假情报是失真规则表的事，研判模块只负责“被骗得合乎逻辑”）；
• 不做自动合并同源情报——两条来源不同的报告即使内容相同也是两条证据，合并与否由加权规则自然体现；
• 不做“参谋的直觉”类启发式智能——第一版全部查表，智能留给参数调优，不留给黑箱。
8. 交付物与工作量
交付物： 研判函数（纯函数库）、参数表 v1（带 hash）、三组金标准研判夹具、六条断言（进 CI）、hj assess 命令。
工作量估计：核心约 200 行 + 夹具一天。 全部可在真引擎动工前完成并验收完毕。
9. 独立性说明：为什么是它
候选模块	独立开发？	结论
回放系统	✗ 依赖确定性引擎	缓
过滤/延迟/失真	半独立，但产出需管线消费才有意义	缓
敌情研判	✓ 输入手写、输出落档、纯函数、无随机	即做
它还是少数越早做越划算的模块：研判规则的手感（矛盾怎么降信、断供多快变盲）需要大量人肉试错，提前到阶段 1–2 完成，阶段 3 认知管线合流时它已是老兵，敌军 AI 接入时 belief_snapshot 现成——下游三份任务书（决策日志、情报账本对质、信念轨迹图）全都踩在它上面。
盲区声明： 研判模块保证“从情报到判断的推理可复核”，保证不了“情报本身可信”——垃圾进垃圾出，来源可信度该多少是失真规则表和参数扫描的事。参谋再高明，也变不出侦察兵没送来的消息——研判模块的边界，就是迷雾玩法的边界。

敌军决策模块 · 任务书
继续按同一标准抽取：现在就能开工、不依赖引擎和任何未建模块。下一个是敌军决策模块——敌军 AI 的“司令部”：读入自己那份敌情研判（就是上一份任务书的输出文件），加上性格参数，定下决心、产出命令。全程纯逻辑运算，输入手写可造，输出落档可验——和研判模块一样，能提前两个阶段独立量产。
1. 模块定位
敌方的参谋作业 + 司令部决断：拿本方的信念状态（“我以为敌军在哪、多少兵力、多大把握”）+ 性格参数（谨慎/冒进/信任阈值），在候选行动集里评分定案，输出一份可执行的决定。它是：
• 决策日志 chosen 字段的生产者——候选评分定案这一步就在这里；
• 玩家对手的全部灵魂——玩家感受到的“对手在赌、在诈、在犹豫”，全部源自评分规则的手感；
• 对称性断言的主战场——它的输入只有信念状态，引擎真相没有进入的通道，公平靠结构保证。
2. 前置依赖（几乎没有）
• 信念状态 schema 已定稿——恰好是研判模块的输出格式，两份任务书接口天然咬合；
• 候选行动集可先用桩版清单（前进/固守/撤退/侦搜 4–6 种），每个行动的执行效果由真引擎将来解释，本模块只管“选哪个”；
• 输入手写可造：一份信念状态 JSON 即可开工；输出是一份决定文件，暂无消费者也能独立验收；
• 不依赖引擎、不依赖 rng（评分确定性，平分时按固定规则破序）。
插入时点：与研判模块同期，阶段 1–2 即可动工。 两个模块合起来，就是一条完整的“AI 认知→决断”链，全部提前于真引擎完成。
3. 输入 / 输出
输入一：信念状态（研判模块的输出，也可手写夹具）：
{”turn“: 47, ”unit“: ”enemy_div_72“,
 ”est_position“: [116.48, 34.60],
 ”est_strength“: 0.68,
 ”confidence“: 0.52, ”stale_turns“: 2}
输入二：性格参数表（查表制，全表带 hash）：
{”profile“: ”cautious“,
 ”aggression“: 0.35, ”risk_tolerance“: 0.3,
 ”min_confidence_attack“: 0.6, ”stale_sensitivity“: 1.5}
输出： 一份决定 + 完整评分现场（评分现场即决策日志的素材，一并落档）：
{”turn“: 47, ”unit“: ”enemy_div_72“,
 ”decision“: ”withdraw“,
 ”to“: [116.30, 34.40],
 ”scores“: [{”action“: ”withdraw“, ”score“: 0.61},
            {”action“: ”hold“, ”score“: 0.48},
            {”action“: ”advance“, ”score“: 0.22}]}
评分规则第一版（查表，无智能）：
规则	内容
态势评分	每个候选按“估计兵力比 × 行动类型系数”计基础分
置信闸门	confidence 低于 min_confidence_attack 时，进攻类候选一律不得最高分
陈旧折价	stale_turns 越高，越倾向保守行动（情报变旧，胆子变小）
性格偏置	aggression 对进攻类加成、risk_tolerance 对冒险行动的分数下限做削平
破序固定	平分时按候选清单固定顺序取前者——不留任何随机性
4. 四条实现铁律
1. 只认两个输入文件——函数签名就是“信念状态 + 性格参数 → 决定与评分现场”。参数表之外不读任何东西，引擎真相在类型上就进不来。对称性断言由此从架构上成立，不需要审查善良；
2. 评分现场先落档，决心后定案——候选评分在 decision 定下之前写入档案（先记录后定案，与决策日志同一纪律），日后每次决策的“为什么”都有原始现场可查；
3. 性格参数即参数表，绝不写死在代码里——谨慎的 72 师、冒进的整编 11 师只是两张不同的参数卡。历史上“邱清泉为什么迟缓”这类问题，答案必须是“调哪个参数”，而不是“改哪行代码”；
4. 确定性从第一版就有——纯函数、无随机、固定破序，同输入永远同输出，零成本通过 CI 确定性断言。
5. 验收断言（全部用手工夹具）
• 金标准决断夹具 ×3：手写三份信念状态（优势/劣势/情报残缺），手算期望决定，逐字段比对；
• 置信闸门：confidence 0.4 + aggression 0.9，断言进攻候选不当选——低把握不冒进是这条链上最重要的行为不变量；
• 性格可区分：同一份信念状态，喂“谨慎”与“冒进”两张参数卡，断言决定不同且 diff 可归因到具体参数；
• 断供变保守：同一态势、stale_turns 从 0 扫到 5，断言决定沿“进攻→固守→撤退”单调滑移；
• 评分现场完整：抽查任意一条决定，按参数表人肉重算各候选评分，与档案一致；
• 参数指纹：改任一参数 → hash 变化 → 同夹具决定 diff 可归因；
• 无真值通道：类型审查 + 夹具验证——输入文件中构造畸形字段（ truth 冒充信念），断言模块无法读到（读不到即安全）。
6. 使用方式（第一版）
不建界面，一个命令：
hj decide —beliefs records/beliefs_turn47.json \
          —profile params/cautious.json
# 输出 records/decisions.jsonl（追加）+ 决定文件
开发期是独立小工具：捏各种信念状态喂它，看决定合不合军事常识——这一步的手感直接决定未来对局的“对手像不像人”。将来管线合流，同一函数原样嵌入，输入从文件换成内存流，接口不变。
7. 明确不做
• 不做多单位协同（几个师怎么配合是“敌军战役意图”层的事，另立任务；本模块一次只决一个单位）；
• 不做学习/自适应——第一版全部查表，参数调优靠 hj batch 扫描，不留给黑箱；
• 不做行动的可行性校验（“撤退目的地是否有路”是引擎的事）——本模块产出意图，可行性由引擎裁决后回炉重决，接口上把这条回路留出来即可。
8. 交付物与工作量
交付物： 决策函数（纯函数库）、性格参数卡 v1（谨慎/均衡/冒进三张，带 hash）、金标准决断夹具 ×3、七条断言（进 CI）、hj decide 命令。
工作量估计：核心约 200 行 + 夹具一天。 与研判模块合计约 400 行，就构成敌军 AI 的完整大脑雏形——比原计划提前两个阶段。
9. 独立性说明与合流路径
候选模块	独立开发？	结论
翻译器/参谋回执	半独立，但脱离真实命令语言意义有限	缓
过滤/延迟/失真	需管线消费	缓
敌军决策	✓ 输入手写、输出落档、纯函数、无随机	即做
合流路径（三份任务书的会师点）：
阶段1-2  研判模块 + 决策模块 独立完成（本册）
             │ 手写情报 → 研判 → 决策 → 落档，全链人肉跑通
阶段3     真引擎供给真实事件流 → 情报账本登记 → 研判改吃管线
             → 决策输出直接进翻译器 → 决策日志同回合挂牌
验收      决策日志的 belief_snapshot 与 chosen，
          分别正是这两个模块的输出——三卷案卷在合流日自动对上
一句话收束：研判模块管“我们认为敌人怎样”，决策模块管“因此我们怎么办”——两个纯函数、四百行代码，在真引擎开工之前就把敌军 AI 的脑子和胆子都造好并验收完毕。等战场（引擎）建成时，对手已经会思考了。
盲区声明： 决策模块保证“从判断到决心的推理可复核、可调参”，保证不了“这个对手打起来有意思”——决定的手感好不好玩，仍要等对局里真人皱眉才能知道。参谋作业可以提前量产，对手的灵气只能在对局中长出来。
